# Февральский расчёт и воспроизводимость

Выполнены 56 запусков: T1/T2, ежедневно в 18:00 UTC с 31 января по 27 февраля
2026 года, горизонт 48 часов. `documented_forecast.csv` содержит 2 688 строк
с идентификаторами турбины, origin, выпуска погоды и модели. Последние 48 строк
по времени назначения выходят в март по Asia/Almaty. Альтернативный
`documented_daily_forecast.csv` берёт первые 24 часа каждого запуска: 1 344
непересекающиеся строки, ровно 672 часа февраля на каждую турбину.
Мощность нормализованная, не МВт. Время в CSV — UTC, февраль определяется
по Asia/Almaty (UTC+5).

## Какая погода используется

Запрашивается конкретный выпуск ECMWF IFS по координатам каждой турбины через
[Open-Meteo Single Runs](https://open-meteo.com/en/docs/single-runs-api).
Сохраняются полный исходный JSON, параметры запроса, время получения сейчас,
контрольные суммы исходного ответа и нормализованного полного выпуска.
Это не фактическая погода и не синтетический fixture.

Для origin в 18 UTC выбирается выпуск **00 UTC предыдущего дня**, то есть
возрастом 42 часа. Все целевые часы входят в горизонт этого выпуска. Это
консервативный выбор; он может ухудшать качество относительно свежего выпуска.

Провайдер описывает хранение отдельных выпусков, но также использует слово
*hindcasts* для исторического ECMWF и приводит лишь типичную задержку публикации.
Публичные документы не доказывают точное время доступности каждого ответа в прошлом.
Поэтому `available_at=null`, `availability_verified=false`,
`provenance_status=provider_documented`. Поле `assumed_available_by=run+24h` —
**допущение**, не фактическое время получения или публикации. Этот же статус
сохранён в каждой строке итогового CSV.

`report.json` разделяет полный вычислительный результат
(`complete_forecast_coverage=true`) и доказанную историческую доступность
(`historical_availability_verified=false`, `full_february_replay=false`).
Без подтверждения провайдера или исторических записей приёма нельзя заявлять
строго доказанное выполнение требования «доступен на тот момент» для всех запусков.
Прежний строгий режим с внешним свидетельством сохранён отдельно и не ослаблен.

## Повторить расчёт

Из корня проекта, с подготовленными моделями (см. README):

```sh
python -m scripts.fetch_replay_weather
python -m scripts.replay --weather-source provider-documented --output-dir artifacts/february_replay
```

Загрузчик получает 56 ответов; при повторе проверяет кеш и не скачивает его
заново. Ошибки и пропуски перечисляются в `artifacts/replay_weather/fetch_report.json`.
Повреждённый кеш не перезаписывается молча. Проверка без сети:

```sh
python -m scripts.fetch_replay_weather --cache-only
python -m scripts.replay --weather-source provider-documented --output-dir artifacts/february_replay_check
```

Сам replay читает только локальный кеш, пишет настоящий входной CSV и вызывает
ту же модель, что live-демо. В его процессе нет обучения, OpenAI или сетевых запросов.
При неполном расчёте CLI возвращает код 2 и пишет `partial_forecast.csv`.
Успешный код 0 означает завершённость вычисления, а не подтверждение доступности.
Без явного `--weather-source provider-documented` используется прежний строгий
архивный режим; он не принимает данные с неподтверждённой доступностью.

## Точность и оставшиеся внешние данные

Модели заморожены на завершённых часах до 31.01.2026 18 UTC. Февральская погода
не использовалась для переобучения или выбора модели. Фактической февральской
мощности в исходных файлах нет: MAE/RMSE за февраль не вычисляются.
Хронологическая диагностика на доступных данных описана в
[FORECASTING_REPORT.md](../FORECASTING_REPORT.md); это не оценка точности этих
февральских прогнозов. Часовой пояс/границы интервалов SCADA и знаменатель
нормализации всё ещё требуют подтверждения владельцем данных.

Источники и атрибуция: [Open-Meteo](https://open-meteo.com/), ECMWF;
[Single Runs API](https://open-meteo.com/en/docs/single-runs-api),
[ECMWF API](https://open-meteo.com/en/docs/ecmwf-api),
[история операционных версий ECMWF](https://www.ecmwf.int/en/forecasts/documentation-and-support/changes-ecmwf-model).
Погодные данные Open-Meteo предоставляются по CC BY 4.0; атрибуция сохраняется
в переносимом комплекте. Версия модели 49r1 работала операционно в феврале 2026,
но это само по себе не устраняет неоднозначность происхождения конкретного архива.

## Готовый комплект

[CSV, отчёт и ZIP](../deliverables/february_2026/README.md) включены в репозиторий.
Комплект содержит 177 файлов и воспроизводится без погоды/LLM/обучения по сети.
После переноса в другой каталог оба CSV получились побайтно одинаковыми.
Все 165 тестов прошли. Python/scikit-learn должны соответствовать manifest.

Собрать новый комплект из проверенного результата:

```sh
python -m scripts.package_replay --report-dir artifacts/february_replay --output-dir artifacts/submission/new_february_package
```

Нужен новый выходной каталог. Существующий пакет не перезаписывается.
Проверяются 56 входных CSV, соответствие погоде, модели, полнота результатов,
метаданные и контрольные суммы. Новые реестры моделей используют относительные
пути, чтобы перенос папки не требовал правки абсолютных путей.
