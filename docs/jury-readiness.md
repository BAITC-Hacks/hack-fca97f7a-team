# Сверка с заданием жюри

Источник: [исходное описание кейса](../data/HackAlem%20AI_%20Agentic%20AI%20для%20прогнозирования%20выработки%20ВЭС.md). Документ разделяет фактическое состояние проекта и границы февральского демо.

| Критерий жюри | Вес | Что можно показать и проверить | Ограничение |
|---|---:|---|---|
| Соответствие задаче и работоспособность | 25 | T1/T2, выбор 1–28 февраля, 24/48 часов, ежедневные исторические расчёты через погодный CSV, график и чат | 56 февральских расчётов выполнены; доступность погодных выпусков на тот момент предполагается, не доказана для каждого выпуска |
| Техническая реализация | 25 | Раздельные адаптеры погоды и объяснения, валидируемый CSV как реальный вход модели, отдельные модели турбин, проверка источника/времени/контрольных сумм, FastAPI + React | «Agentic AI» здесь — управляемая последовательность инструментов и проверок, без автономного выбора произвольного плана |
| README и воспроизводимость | 25 | Команды запуска, обучения и проверок в корневом README; исходные данные, код и схема CSV в репозитории | Для февральского расчёта приложен переносимый комплект моделей и погоды, проверен без сети; обучение с нуля требует сети и времени |

По тексту задания участники должны восстановить прогнозы за 1–28 февраля 2026 года, начиная с выпуска 31 января и последовательно обновляя расчёт. На каждом шаге нужна **погода, доступная на момент этого шага**. Февраль доступен в основном интерфейсе, а `scripts/replay.py` воспроизводит весь период. Для 28 дней назначения используются origins 31 января — 27 февраля в 18:00 UTC: первый целевой час каждого запуска — местная полночь. Получены все 56 отдельных выпусков Single Runs. Выполнены 2 688 прогнозных строк и 1 344 строки непрерывного февраля; [отчёт и команды](february-replay.md). Доступность выбрана по консервативному правилу и явно помечена как предполагаемая; подтверждённых времён публикации всех выпусков нет. Ретроспективный Historical Forecast API, применённый для обучения, не подтверждает доступность конкретного выпуска в прошлом. Истории турбин заканчиваются январём; февральской фактической мощности для итоговой ошибки тоже нет.

На защите покажите 1 февраля: момент расчёта 31 января → исторический выпуск
погоды → входной CSV → график/таблица → объяснение → вопрос. Затем переключите
на 2 февраля и покажите новый момент расчёта 1 февраля. Завершите 28 февраля и
месячным CSV с 672 часами на турбину. Для 48 часов мартовский хвост остаётся
виден; он не включается в непрерывный февральский ряд.

Статус `provider_documented` и `available_at=null` нельзя скрывать или переводить
в `verified` только потому, что график построен. Нужны достаточные свидетельства
происхождения конкретных операционных выпусков и доступности до момента решения;
типичная задержка из документации сама по себе не устанавливает время публикации
каждого выпуска. Это оставшийся блокер строгого заявления о полном соответствии.

[Контракты](../CONTRACTS.md), [отчёт о модели](../FORECASTING_REPORT.md) и
[аудит данных](../DATA_MODEL_HANDOFF.md) описывают проверяемые границы. Метрики
хронологической проверки — диагностика на ретроспективном погодном ряде, не
подтверждённая точность этих 24/48-часовых прогнозов. Отсутствие фактической мощности
не мешает показать требуемую последовательность расчётов, но исключает февральские
MAE/RMSE.
