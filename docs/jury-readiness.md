# Сверка с заданием жюри

Источник: [исходное описание кейса](../data/HackAlem%20AI_%20Agentic%20AI%20для%20прогнозирования%20выработки%20ВЭС.md). Документ разделяет фактическое состояние проекта и объём нынешнего live-демо.

| Критерий жюри | Вес | Что можно показать и проверить | Ограничение |
|---|---:|---|---|
| Соответствие задаче и работоспособность | 25 | T1/T2, текущий погодный прогноз по координатам, 24/48 почасовых значений, повторный расчёт после обновления погоды | Полный февральский replay из исходного задания исключён из текущего демо |
| Техническая реализация | 25 | Раздельные адаптеры погоды и объяснения, валидируемый CSV как реальный вход модели, отдельные модели турбин, проверка источника/времени/контрольных сумм, FastAPI + React | «Agentic AI» здесь — управляемая последовательность инструментов и проверок, без автономного выбора произвольного плана |
| README и воспроизводимость | 25 | Команды запуска, обучения и проверок в корневом README; исходные данные, код и схема CSV в репозитории | Обучающие артефакты генерируются локально; первое получение погодного ряда требует сети и времени |
| Ценность и применимость | 15 | Живой прогноз, визуализация ветра и мощности, скачиваемые CSV, объяснение и вопросы по тому же результату | Нет подтверждённой точности на настоящих 24/48-часовых выпусках; значения мощности нормализованы, не в МВт |
| Потенциал развития и оригинальность | 10 | Проверяемое происхождение погодных данных и входа модели, возможность заменить погодный/LLM-адаптер, локальное сохранение результатов | Для оценки полезности в эксплуатации нужны настоящие выпуски на дальних горизонтах и последующие фактические измерения |

По тексту задания участники должны восстановить прогнозы за 1–28 февраля 2026 года, начиная с выпуска 31 января и последовательно обновляя расчёт. На каждом шаге нужна **погода, доступная на момент этого шага**. `scripts/replay.py` и архивный адаптер существуют как внутренние инструменты, но подтверждённых погодных выпусков для всех запусков нет. Ретроспективный Historical Forecast API, применённый для обучения, не подтверждает доступность конкретного выпуска в прошлом. Истории турбин заканчиваются январём; февральской фактической мощности для итоговой ошибки тоже нет.

На защите разумно показать один полный живой проход: выбор турбины → получение погоды → скачивание входного CSV → почасовой результат → объяснение → вопрос → обновление погоды. Для воспроизводимой технической проверки жюри могут запустить тесты и посмотреть [контракты](../CONTRACTS.md), [отчёт о модели](../FORECASTING_REPORT.md) и [аудит данных](../DATA_MODEL_HANDOFF.md). Числа из хронологической проверки модели следует представлять как диагностику на ретроспективном погодном ряде, без заявления подтверждённой точности живого прогноза на 24/48 часов.
