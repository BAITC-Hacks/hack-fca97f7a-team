# План и границы проекта

## Текущее демо

Основной сценарий — февраль 2026: турбина → день 1–28 февраля → 24/48 часов →
операционный архивный выпуск ECMWF Open Data → проверенный CSV → замороженная модель →
график мощности и ветра, таблица, объяснение и чат по сохранённому прогнозу.
Для выбранного дня расчёт выполняется как на предыдущий день в 23:00 Asia/Almaty
(18:00 UTC). Переход к следующему дню воспроизводит ежедневное обновление.
Текущий прогноз остаётся отдельным режимом. Fixtures не показываются в UI.

## Организация

- `backend/api.py` — HTTP, валидация запросов и раздача React.
- `backend/services/agent.py` — последовательность инструментов и численный анализ.
- `backend/adapters/` — погода, LLM, хранение результатов.
- `backend/ml/` — исходные данные, CSV-признаки, обучение и инференс.
- `backend/core/contracts.py` — общие типы, ограничения и пути.
- `frontend/` — активный интерфейс.
- `scripts/` — воспроизводимые CLI обучения и оценки.
- `tests/` — проверки без платных вызовов.
- `legacy/` — прежний Streamlit-прототип, не основной способ запуска.

Не добавлять БД, очереди или дополнительные уровни агентов ради демо.
Числа вычисляет модель и код; LLM объясняет готовый результат.

## Требования жюри

Основной интерфейс должен показывать исторический процесс, а не только готовый
файл. 28 дат назначения покрывают 1–28 февраля: origins с 31 января по 27 февраля,
по 2 турбины. Для 48 часов сохраняется мартовский хвост последнего запуска;
непрерывный февральский CSV использует первые 24 часа каждого запуска.

Основной источник — операционные выпуски ECMWF из официального публичного
архива. Для каждого используемого объекта проверяются серверное время до origin,
идентичность GRIB, сроки, единицы и хеши. Погодные наблюдения не подставляются.
Полный прогон завершён: 56/56 запусков, 2 688 строк на 48 часов и 1 344 строки
непрерывного февраля. Независимый аудит прошёл 289 проверок. Основной комплект —
`deliverables/february_2026_operational`.

Предыдущий Open-Meteo-комплект `provider_documented` остаётся отдельно условным:
`available_at=null`. Его доступность не повышается автоматически до verified.
Февральской фактической мощности в data нет; это ограничение оценки качества,
а не повод заменять прогнозные погодные входы измерениями.
Подробнее: [февральский расчёт](docs/february-replay.md) и
[соответствие критериям](docs/jury-readiness.md).
