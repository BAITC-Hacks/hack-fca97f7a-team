# План и границы проекта

## Текущее демо

React → FastAPI → Open-Meteo ECMWF IFS → проверенный CSV → обученная модель
мощности → таблица и график → объяснение и вопросы по сохранённому прогнозу.
Пользователь выбирает T1/T2 и 24/48 часов. В интерфейсе только настоящая погода;
синтетические fixtures используются внутри тестов, без автоматической подмены.

## Организация

- `backend/api.py` — HTTP, валидация запросов и раздача React.
- `backend/services/agent.py` — последовательность инструментов и численный анализ.
- `backend/adapters/` — погода, LLM, хранение результатов.
- `backend/ml/` — исходные данные, CSV-признаки, обучение и инференс.
- `backend/core/contracts.py` — общие типы, ограничения и пути.
- `frontend/` — активный интерфейс.
- `scripts/` — воспроизводимые CLI обучения и оценки.
- `tests/` — проверки без платных вызовов.
- `legacy/` — прежний Streamlit-прототип, не основной способ запуска.

Не добавлять БД, очереди или дополнительные уровни агентов ради демо.
Числа вычисляет модель и код; LLM объясняет готовый результат.

## Требования жюри

Исходное задание отдельно требует воспроизвести февраль 2026 с погодными
прогнозами, доступными на каждый исторический момент. Это не выполнено одним
live-демо. Архивный режим исключён из интерфейса. По следующему запросу пользователя
реализован отдельный вычислительный февральский прогон на Single Runs, с явной
оговоркой о предполагаемой доступности выпусков. См. docs/february-replay.md.
Подробнее: [соответствие критериям](docs/jury-readiness.md).
