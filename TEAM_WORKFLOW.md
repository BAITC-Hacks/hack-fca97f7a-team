# Совместная работа без расхождения контрактов

Перед новой задачей, после сохранения своих изменений коммитом:

```sh
git fetch origin
git merge origin/main
```

Не заменять целиком `backend/adapters/weather.py`, `backend/api.py`, `App.tsx` или общие контракты версией
из старой ветки. В main уже есть live-погода, редизайн, экспорт графика, модельные
профили и русский интерфейс. Из параллельных реализаций переносить нужное поведение
и тесты с сохранением текущего публичного контракта.

| Владелец | Граница согласования |
|---|---|
| A — backend/погода | HTTP-поля, время live/архива, происхождение, кеш |
| B — модель | схема CSV, профиль модели, единицы и высоты погоды |
| C — интерфейс/чат | DTO, состояния запросов, сообщения и контекст прогноза |

При изменении границы написать короткий пример запроса/ответа в CONTRACTS.md
и сообщить затронутым разработчикам. Изменять только свою часть файла; не удалять
чужие незакоммиченные изменения. Новые интеграции проверять на актуальном main.

Перед передачей:

```sh
python -m pytest -q
npm --prefix frontend run build
git diff --check
```

Автотесты не вызывают платные API. Отдельно указывать, какие проверки использовали
моки, какие — настоящий погодный API. Не объявлять февральскую сдачу завершённой
по результату текущего live-прогноза или replay на fixtures.

Ветки команды не переписываются принудительно. Финальное слияние должно сохранить
обе истории и актуальные контракты; push без force.
