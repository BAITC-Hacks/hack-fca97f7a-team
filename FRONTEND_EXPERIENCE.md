# Samal — пространственный интерфейс прогноза

Пространственный слой использует React 19 + TypeScript + Vite и существующий
FastAPI. При интеграции сохранены актуальные модули `backend/` из main;
обучение и числовой pipeline не менялись в рамках UI. Нет нового маршрутизатора,
авторизации, БД или очередей.
Основной сценарий остаётся weather → проверенный CSV → модель → числовой
результат → объяснение по серверному ID.

## Что реализовано

- Полноэкранная Земля с локальной текстурой NASA Blue Marble, атмосферой,
  освещением и маркерами по пользовательским координатам. Близкие T1/T2 разведены
  подписью с привязкой к исходным точкам; выбор также доступен текстовым списком.
  Сначала появляется лёгкая 2K-текстура, затем подходящий уровень 4K или 8K.
  Оптимизированные WebP поставляются вместе с приложением; внешних загрузок
  во время просмотра нет. Уровень учитывает экран, память и лимиты WebGL.
- Единая 3D-сцена и обратимый пружинный переход к иллюстративной турбине.
  Вращение, масштаб и возврат работают во время перехода. В начале Земля
  слегка движется: небольшой вступительный зум и вращение около 0,69°/с
  до первого касания, нажатия клавиши, масштаба или выбора. Затем автоматическое
  вращение не возобновляется; reduced motion отключает это движение. Рельеф не выдаётся за геодезическую модель площадки.
- React управляет выбранными данными; Three.js меняет камеру, свет и геометрию
  в отдельном цикле кадров. Сцена загружается лениво. Качество выбирается
  автоматически или в параметрах; при недоступном WebGL сохраняется интерфейс.
- Временная шкала, график, текстовые показатели и Samal используют один индекс
  реального прогнозного ряда. Шкала немедленно реагирует на перетаскивание и
  клавиатуру. Воспроизведение запускается только пользователем, останавливается
  ручным выбором и не зацикливает прогноз незаметно. В ночном состоянии
  кнопка «День» выбирает существующий дневной час из ряда по положению Солнца;
  она не осветляет ночь искусственно и отсутствует без подходящих часов.
- Сохранены live-прогнозы на 24/48 часов, две турбины, почасовая таблица,
  мощность и ветер с разными шкалами, CSV/PNG/SVG, точный вход модели и сравнение
  общих часов между запусками. Обновление очищает погодный кеш выбранной турбины
  перед расчётом. В интерфейсе нет синтетических/архивных режимов и baseline-линии.
- При первом открытии шапка, заголовок и список проявляются небольшими
  последовательными пружинными движениями. Ввод доступен сразу; возвращение
  к Земле не повторяет вступление. Samal в покое слегка дышит светом и медленно
  движет воздушные элементы; это декоративный живой образ, не погодное измерение.
  Reduced motion отключает эти эффекты.
- Явная кнопка «Чат с Samal» с иконкой сообщения и подписью «Спросить о прогнозе»
  открывает помощника. Абстрактная фигура ветра остаётся частью кнопки.
  На большом экране панель не
  блокирует временную шкалу и сцену; на телефоне открывается доступный нижний
  диалог. Навигационные команды явно локальные. Общие вопросы и объяснение
  используют существующие серверные адаптеры и хранимый forecast ID.
- Состояния Samal отражают реальные запросы сохранённого результата, обновления
  погоды, прогноза, объяснения и вопроса.
  Сервер не стримит промежуточные этапы, поэтому интерфейс их не симулирует.
  Фактический trace доступен после результата во вкладке источников.

## Границы данных

Интерфейс предлагает только **live**: текущий прогноз Open-Meteo ECMWF IFS.
Сервер выбирает текущий UTC-час; ряд начинается с origin+1h. Это прогноз,
не показания SCADA. Для live используется отдельный профиль модели
`open_meteo_ecmwf_ifs_10m`, обученный на погоде этого источника и измеренной
мощности. Ветер 10 м — признак провайдера, не показание у ротора. Точность
24/48-часового прогноза пока не подтверждена. Источник, время получения,
погодный кеш, модельный профиль и его ограничения видимы в аналитике.
Тихой замены на fixtures нет. Синтетика и условный февральский replay остаются
внутренними инструментами main и не добавляются в пользовательские селекторы.

В localStorage хранится только последний live forecast ID. При перезагрузке
клиент вызывает `GET /api/forecasts/{id}`, проверяет результат, восстанавливает
турбину и горизонт, но сохраняет вход через Землю. Данные отмечены как
сохранённые, исходное время получения погоды остаётся видимым. Ни погода,
ни модель, ни LLM при восстановлении не вызываются. Объяснение загружается
кнопкой «Получить объяснение». Неизвестный/просроченный ID очищается;
ошибка сети видима. Отключённый localStorage не мешает текущему расчёту.

API передаёт только почасовой ветер, температуру и прогнозную мощность. Поэтому:

| Поле / визуальный эффект | Источник |
|---|---|
| Ветер, температура, мощность | Точный активный прогноз API |
| Солнце / время суток | Вычисление по UTC-времени и координатам |
| Вращение ротора | Ограниченная нелинейная визуальная функция ветра с инерцией |
| Облачность, направление ветра, осадки | Неизвестны; не выдумываются |
| Влажность, видимость, код погоды | Неизвестны; не выдумываются |
| Реальные RPM и операционный статус | Не предоставлены; визуальная скорость не называется измеренной |
| Рельеф и геометрия турбины | Иллюстрация, не обследование площадки |
| Трава, воздушные частицы, солнечные лучи | Художественное окружение; скорость движения связана с ветром, направление условное |
| SCADA, аварии, неопределённость P10/P90 | Не поддерживаются текущим контрактом |

Поля для дополнительных погодных признаков предусмотрены в нормализованном
адаптере как nullable. Дождь, туман и облачность не включаются по придуманным
паттернам времени или ветра. Их расширение требует согласованного DTO/провайдера.

Мощность остаётся [0, 1], интерфейс показывает проценты этой шкалы. Это не МВт,
МВт·ч или доказанная доля паспортной мощности. Нет суммарной мощности фермы,
неподтверждённых показателей точности или автоматического определения аварий.

## Samal и контекст

`assistant/agentTools.ts` — небольшой проверяемый allowlist команд, а не
LLM tool-calling. Он может:

- выбрать зарегистрированную турбину и дождаться её числового прогноза;
- найти в полученных рядах минимум, максимум или наибольшее почасовое снижение;
- выбрать первый час следующего дня и начать управляемое воспроизведение;
- открыть график / таблицу и вернуть Землю;
- объяснить выбранную точку данными этого часа и предыдущего.

Примеры: «Покажи турбину 2 завтра, когда мощность минимальна», «Покажи максимум»,
«Покажи самое сильное падение», «Почему снизилось здесь?», «Открой график»,
«Вернись к Земле». «Завтра» означает календарный день после **даты выпуска**
в часовом поясе турбины. Часы вне горизонта не выдумываются. Неизвестные турбины
отклоняются. Шестичасовые вопросы сохраняют серверный расчёт окон.

Контекстный ответ «здесь» локальный: он сообщает выбранный час, нормализованную
мощность, ветер, температуру и изменение за час, с оговоркой о причинности.
Он не маркируется OpenAI-ответом. Общие вопросы отправляются серверу с ID
прогноза, выбранным UTC-часом, турбиной и часовым поясом; клиент не передаёт
замещающий ряд предсказаний. Источник ответа и fallback видимы.

Ненавязчивая подсказка «Момент перемены» строится только при фактическом снижении
на 5 и более процентных пунктов нормализованной шкалы между соседними часами.
Она не называется неисправностью оборудования. Нажатие выбирает этот час.

## Состояние и отмена

App сохраняет AbortController и epoch для восстановления/прогноза/объяснения,
отдельный token для действий Samal и запроса вопроса. Смена турбины, горизонта
или явное обновление погоды очищает предыдущие числа, анализ и диалог;
устаревшие ответы отбрасываются.
Ручное перемещение времени / возврат / новая команда отменяют незавершённое
действие Samal. Числа появляются до объяснения. Ошибка объяснения сохраняет
прогноз. Ошибка погоды сохраняет географический контекст, но не показывает старые
числа под новым запуском или турбиной. Загрузка CSV проверяет актуальность ID ещё
раз перед сохранением файла.

| Почасовая таблица и CSV результата | «По часам», выгрузка CSV; время строки выбирает час сцены |
| Точный входной CSV, схема/столбцы/хеш | «Источники и метод» и кнопка входного CSV в прогнозе |
| Последний сохранённый forecast ID | Безопасный localStorage + GET; восстановление без погоды/модели/LLM, явно отмеченные сохранённые данные |
| Объяснение сохранённого результата по запросу | «Чат с Samal» → «Получить объяснение» |
| Вопросы, реальный backend/model/warning и fallback | Чат; сервер получает сохранённый ID, fingerprint проверяется |
| Предыдущий результат и совпадающие часы | «Сравнение запусков»: число изменений, среднее абсолютное изменение, таблица дельт |
| Ошибки, отмена и устаревшие ответы | AbortController + request/action epoch, очистка старых чисел при смене ввода |

Серверный `backend/`, локальное хранение результатов и февральские CLI/выгрузки
интегрированы из main. UI не модифицирует их числовую логику или артефакты обучения.

## Доступность и производительность

Клавиатура: Tab выбирает элементы, Enter/Space активирует; стрелки и +/-
вращают/масштабируют Землю при фокусе сцены; Escape возвращает к Земле или
закрывает активную панель. Native range поддерживает стрелки/Home/End и сообщает
выбранный час и мощность. В модальных панелях фокус удерживается и возвращается
к открывшей кнопке. Кнопки графика, таблица и реестр сохраняют текстовый путь.

`prefers-reduced-motion` сокращает переходы, отключает декоративное вращение
и избегает интенсивного timelapse. Сокращённая прозрачность и повышенный контраст
получают плотные поверхности. Системные шрифты не требуют внешнего запроса.
Насыщенность зелени, солнечные лучи и мягкая ночная подсветка художественные:
они помогают читать сцену и не выдаются за спутниковые наблюдения. На мобильном
экране сохраняются Земля, турбина, шкала и Samal; аналитика —
прокручиваемый нижний лист. Фактические 60 FPS зависят от устройства; результат
не заявляется как измеренный на всех GPU. WebGL-пакет загружается отдельным чанком.

## Проверки

```sh
python -m pytest -q
npm --prefix frontend run build
npm --prefix frontend run test:scene
node --experimental-strip-types --test frontend/tests/agent-tools.test.mjs
```

Node 22+ с поддержкой strip-types нужен только для небольших проверок команд.
Они проверяют переход T2 + минимум завтра, дату относительно origin/таймзоны,
неполное покрытие, настоящий спад, «здесь», неизвестную турбину, сохранение
серверных шестичасовых вопросов и выбор дневного часа без выдумывания времени. Python-набор использует моки OpenAI, ключ очищен.
Браузерную проверку выполняют с `OPENAI_API_KEY=''`; сценарий — в README.

## Результат проверки 23 сентября 2026

До интеграции обновлённого main прошли **116 Python-тестов**, **7 проверок
сцены/математики**, **8 проверок команд/времени**, TypeScript и production-сборка
Vite. После pull a2135fc прошли **165 Python-тестов**, **8 проверок сцены**
(включая новый ветер) и **8 проверок команд**, TypeScript.
Python-тесты используют моки OpenAI и очищенный ключ. Локальные проверки сцен
не подменяют замер производительности GPU.

В Chromium на desktop и экране 390 × 844 проверены настоящие пользовательские
действия: вращение, прерванный перелёт Земля → T1 → Земля → T2, 24/48 часов,
дневной переход к существующему часу, синхронизация графика/шкалы/показателей,
воспроизведение и его остановка вручную, Samal → минимум завтра для T2,
контекст «здесь», закрытие только активной панели по Escape и отсутствие
горизонтального переполнения. Запрос 8K-текстуры наблюдался в браузере.

До pull проверены реальные текущие прогнозы Open-Meteo и явно подписанные
синтетические сценарии старого режима, загрузки PNG/SVG и обоих CSV.
После pull пользовательский интерфейс оставляет только live, как актуальный main. Входной CSV содержит 48 строк, четыре канонических
столбца; SHA-256 совпадает с именем файла. PNG осмотрен визуально. Браузерный
сервер запускался с пустым `OPENAI_API_KEY`; платных запросов не выполняли.

Отдельно **искусственно** задерживали ответ вопроса и возвращали HTTP 503 от
погодного запроса: ручное движение отменяет старый ответ, ошибка очищает старые
числа и шкалу. WebGL отключали для проверки доступного fallback; reduced motion
проверяли эмуляцией системной настройки. Это проверки отказов, а не утверждение
о сбое реального провайдера. До намеренной инъекции ошибки JavaScript/WebGL
ошибок в браузере не было. Кадровая частота на всём парке устройств не измерена.

## Намеренно не заявлено

Автономный LLM orchestration, прогноз на 7 дней, фактическая SCADA, выявление
поломок, архив без внешних подтверждений, реальная облачность/дождь/туман,
калиброванная неопределённость и замер FPS на широком парке устройств. Текущий
интерфейс не скрывает эти отсутствующие данные за красивой сценой.
