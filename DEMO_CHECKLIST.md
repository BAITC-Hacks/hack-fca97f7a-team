# Приёмка демо

## Пользовательский сценарий

1. Открыть localhost:8000. Выбрать T1, 24 часа, настоящую погоду.
2. Сформировать прогноз. Видны время получения, источник, мощность и ветер
   с отдельными шкалами, затем объяснение по тому же прогнозу.
3. Скачать прогноз CSV, точный входной CSV, PNG и SVG. В пользовательских
   данных нет baseline; строки CSV совпадают с таблицей и горизонтом.
4. Повторить для T2 и 48 часов. При повторе в течение пяти минут погода может
   прийти из кеша; исходное время получения остаётся видимым.
5. Нажать обновление погоды. Вызов должен обойти кеш и заново рассчитать прогноз.
6. Задать вопрос и сменить турбину/горизонт во время запроса: старый ответ не
   появляется под новым прогнозом.
7. Проверить ширину 390 px: элементы доступны, график не перекрывает кнопки.

## Устойчивость

- Недоступность погодного провайдера не превращается в скрытые fixtures.
- Переход через границу UTC-часа допускает один безопасный повтор.
- Недоступность LLM сохраняет числа и даёт русское расчётное объяснение.
- Сохранённый прогноз доступен после перезапуска сервера по прежнему ID
  в пределах политики хранения. Повреждённый JSON или CSV не принимается.
- Настоящий исторический архив без проверенного свидетельства остаётся закрытым.

## Воспроизводимый февральский расчёт

```sh
python -m scripts.replay --mode fixture --days 2 --output-dir artifacts/replay_fixture
python -m scripts.replay --mode archive --output-dir artifacts/replay_february
```

Первый запуск — только проверка четырёх сценариев, 192 строки синтетической
погоды. Второй проверяет 56 запусков и 2 688 строк. При пропусках CLI возвращает
код 2, создаёт `partial_forecast.csv` и перечисляет все ошибки в `report.json`.
`forecast.csv` создаётся только для полного проверенного архивного replay.
Истинная выработка февраля отсутствует: метрики февраля не рассчитываются.
