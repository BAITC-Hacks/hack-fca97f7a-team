# Задачи команды: демо прогноза мощности ВЭС

## Согласованный сценарий

Турбина → текущий прогноз Open-Meteo → CSV → модель мощности → таблица,
график и объяснение на русском → вопросы по выбранному прогнозу.
Исторический архив и февральский replay исключены из задач демо по решению пользователя.

## Реализовано

- [x] React + FastAPI, T1/T2, горизонты 24/48 часов.
- [x] Настоящая погода Open-Meteo ECMWF IFS; CSV действительно читается моделью.
- [x] Отдельный профиль моделей для погоды провайдера, обучение через CLI.
- [x] График мощности и ветра с отдельными шкалами; таблица и CSV/PNG/SVG.
- [x] Объяснение и вопросы по серверному forecast ID; явный расчётный fallback.
- [x] Память последних 10 сообщений, выбранный период и новый разговор при новом
  прогнозе. Python-инструменты выбора N часов, сравнения периодов, погоды,
  средней мощности и резких изменений. Таблицы и числа считает сервер.
- [x] Русский интерфейс, обновление погоды, пятиминутный кеш и время получения.
- [x] Сохранение прогнозов между перезапусками, контроль целостности и срок хранения.
- [x] Защита от запоздалых ответов при смене параметров.
- [x] Baseline исключён из пользовательских результатов и контекста объяснения.
- [x] 199 тестов и сборка React прошли при интеграции актуальной main в dev-a.
- [x] Реальная погода, кеш, обновление и восстановление после перезапуска проверены.
- [x] Браузерные проверки с моками на ширине 390/1280 px.

## Следующие задачи

| Разработчик | Задача | Ожидаемый результат |
|---|---|---|
| A — backend/погода | Проверить отказы и таймауты Open-Meteo в общем сценарии | Понятная ошибка, повторный запрос восстанавливает работу; нет скрытой подмены погоды |
| B — модель | Оценить соответствие погодных признаков и качество модели на доступной хронологической выборке | Воспроизводимые метрики отдельно для T1/T2, описание ограничений и версии модели |
| C — frontend/чат | Проверить полезность ответов и провести пользовательскую репетицию | Русские ответы опираются на текущий прогноз; численные утверждения совпадают с таблицей |

## Общая приёмка

- [ ] Пройти живой сценарий T1/T2 × 24/48 часов: погода, CSV, модель, объяснение, вопрос.
- [ ] Проверить понятность ошибок погоды и LLM, смену параметров и мобильную версию.
- [ ] Проверить выгрузки и согласованность чисел таблицы, графика и объяснения.
- [ ] Подтвердить единицы и трактовку мощности: нормализованная величина, не МВт.
- [ ] Подготовить явный демонстрационный режим на случай отсутствия сети.

Не заявлять точность на будущих 24/48 часах без соответствующей проверки.
Не добавлять БД, очереди или второго LLM-провайдера ради демо.
Автоматические проверки не расходуют платные API-кредиты.
