# Обучение и оценка модели

Рабочая модель уже интегрирована в React + FastAPI через точный входной CSV. Актуальный контракт — [CONTRACTS.md](CONTRACTS.md), команды запуска — [README.md](README.md), исходные числа и ограничения — [DATA_MODEL_HANDOFF.md](DATA_MODEL_HANDOFF.md). Этот файл задаёт воспроизводимую процедуру дальнейшей оценки; ранний план только для Streamlit больше не описывает текущее приложение.

1. `python -m scripts.train --mode fixture` читает отдельно T1/T2 из неизменённых исходных CSV, формирует полные UTC-часы, сохраняет аудит и две локальные модели. Режим `fixture` относится к погоде демонстрации; обучение всегда использует реальные измерения.
2. Обе модели применяют `HistGradientBoostingRegressor(max_iter=100, max_leaf_nodes=15, random_state=42)` к `[wind_speed_ms, temperature_c]`. В версии модели учитываются исходный хэш, канонические часы, временная отсечка, признаки, параметры и версия библиотек. Точность нельзя улучшить простым объявлением другой реализации; сравнение алгоритмов требует отдельной воспроизводимой оценки.
3. Финальное обучение включает только часы с концом не позже `2026-01-31T18:00:00Z`; последний тренировочный час начинается в 17:00 UTC. Запрещено подбирать параметры по февралю. Нулевые мощности остаются, неполные часы и неоднозначные местные времена исключаются с аудитом.
4. Для проверки регрессора выполнить `python -m scripts.evaluate --output-dir artifacts/evaluation`: хронологические development и январский test до февраля, отдельно по T1/T2 и горизонтам 24/48 часа, без утечки из будущего. Отчёт сохраняет MAE, RMSE и R² вместе с периодом и числом часов и сравнивает прогноз с последней известной мощностью на тех же строках; результаты поясняет [EVALUATION_REPORT.md](EVALUATION_REPORT.md). Это оценка по **измеренным** ветру и температуре, а не качество прогноза на погоде провайдера. F1 к этой задаче неприменим: выход непрерывный.
5. Инференс использует `model_input.write_model_input` → `model.predict_power_csv`, с версией схемы `weather-features-v1`, SHA-256, 24/48 UTC-часами и идентичностью турбины. Команда обучения не исполняется в HTTP-запросах.

Февральский пакетный расчёт из 28 ежедневных origin × 2 турбины × 48 часов (2 688 строк, часть в марте) остаётся будущей задачей до получения as-issued погодного архива и подтверждённых координат. Истинные февральские значения в выданных CSV отсутствуют; до их появления нельзя сообщать февральские метрики качества. Высота измеренного ветра, высота ветра будущего провайдера, нормализация мощности и семантика исходной отметки времени требуют подтверждения у владельцев данных.
